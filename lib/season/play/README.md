# Play surfaces

`GET /api/play` is authenticated and never cached. Its read-model contains only catalog id, Category and fictional org, the Player's stored Season Blokbuks, advisory daily capacity, Season status and server time. Call start remains authoritative about the five-a-day limit. A missing score row is a valid zero; missing tables, configuration or authentication dependencies produce 503. An absent Season is explicitly unavailable and disables starting. Upcoming Seasons disable start; ended Seasons permit practice.

The call page starts only on a Player click, resumes an opaque call id from sessionStorage (`tell-active-call`) via an ownership-checked GET, and never stores scores or transcripts locally. A temporary resume failure preserves the pointer, blocks replacement calls and offers an explicit Resume saved call retry. Only confirmed missing/unowned (404) calls clear the pointer; a saved call for another scenario returns to that call. Pre-start practice status uses server time plus locally elapsed time so a skewed browser clock cannot change it. Signed-out visitors return to the signup entry at `/profile?returnTo=…`. Branding and shared navigation come from the Season app shell. No signup endpoint or authentication implementation is introduced here.

`CallScreen` accepts `onComplete(call)` as the results integration boundary. The server's actual result stays in the public call state. Until BS-11 is connected, completion displays a neutral saved-Verdict message and return link; it does not invent a score, lesson, rank or results URL. A failed finish remains on the Verdict screen with the server error and enabled retry.

The Player/session, shared schema, Season and Scorekeeper modules are now merged. Authentication uses the canonical Player lookup and store through the call engine's exported adapter. Production call finalization is wired to the transactional Scorekeeper, including its rules fallback; Play reads the shared tables without substitute migrations or demo records. Actual production schema provisioning and the live integrated flow have not been verified. BS-11 results remain pending at the `onComplete(call)` boundary described above.

Speech uses only the current owned call's `/api/play/calls/[id]` endpoint: JSON `speech` for the latest stored caller line, multipart `audio` for transcription. Transcription fills an editable textarea; Send is separate. Errors preserve typing. Replies are limited to the server’s 1,000-character limit. A context link immediately above the reply moves keyboard focus to the fictional card and fake secrets, keeping them accessible on a phone without scrolling through all controls. Recording streams, pending requests and audio are stopped on revision, active-state change and unmount. The server enforces the reply/time caps; the displayed countdown uses its clock and requests End once at zero, leaving a manual retry available on failure.

Verification covers the authenticated route factory with real Requests, SQL adapters against disposable Postgres, public component rendering and the browser bundle. Fixture-driven browser captures exercise UI only; live ElevenLabs and real phone testing are still required before closing BS-10.
